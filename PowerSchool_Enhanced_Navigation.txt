Enhanced Navigation Customization
How To Customize The Enhanced Navigation Menu
Introduction
With the release of 23.5.0.0 a new enhanced navigation system has been introduced. Navigation Links are stored in the PS SIS Database, under the Navigation and PageCatalog tables. The PageCatalog table holds information specific to the page such as Title and URL. The Navigation table contains a reference to the PageCatalog page and holds the structure of the navigation. To add links to the Enhanced Navigation, customizers will create JSON files that are parsed, and data is then stored in the appropriate tables. Links to custom pages may also be added via the new Custom Links page.

Currently there are two types of navigation supported: App Nav and Detail Nav. The App Nav is the main PowerSchool Left Navigation which contains icons at the root Category level and supports up to 4 levels of information. The Detail Nav supports up to 3 levels of information and does not contain icons for the root Category level.

Additional changes to this work relate to the Student/Staff information sections of the page. If any customizations are being done to these areas, they may not display as they currently do because we are restructuring the information.

Best Practices for Partners
To ensure users have a good experience, please keep our best practices in mind as links are placed in the navigation. Categories should not be added to the root menu. The applications category can be used, or links can be placed in relevant existing categories. Please also ensure links are inserted alphabetically.

Additional UI Changes
Tabs
Along with the UI structure changes of the navigation, pages and workflows were also reorganized. For example, certain workflows which use tabs as a way to navigate, such as Health pages, were reorganized to be a part of the navigations. Due to this change, the old SIS Tabs were deemed unnecessary. The tabs are hidden by default using CSS in the Enhanced Navigation. If tabs are still needed for navigation the class shown_tabs can be added to the "ul" element to ensure the tabs will continue to display as before. But customizers should include the page definitions for each tabbed page as children of a isLandingPage page definition.

The following examples demonstrate how to add the shown_tabs when using either of the SIS tab mechanisms.

Student Alerts
Student alerts have been updated to use new SVG icons and have been moved in to the student details header. In order to ensure custom alerts display correctly a strict HTML format should be followed.

Using PowerSchool Design System SVG icons
To find a desired pds-icon name go to /admin/ui_examples/navigation/showPdsIcons.html to an available SIS. This page shows all available icons and their name.

<a class="dialogM" title="{Your Text}" href="{Path to Alert Template}"> <pds-icon name="{pds-icon name}” style="height:18px;width:18px;"> </a>
Using img tags for png or svg files
<a class="dialogM" title="{Your Text}" href="{Path to Alert Template}"> <img src="{Path to image}" alt="{Alternative Text to the image}"> </a>
Where to Place JSON(s)
Customizers will include their JSONS under pagecataloging/ in their plugin zip folder in one of two ways:

For plugins that need to support pre-23.5.0 SIS it is recommended to provided a separate plugin which contains the JSONs defining the necessary Navigation/PageCatalog records. Zip this plugin and the pre-23.5.0 plugin into a single zip file. Provide instructions to customers stating the plugin with the JSONs should only be installed once they have upgraded to 23.5.0.

For any new plugin beyond 23.5.0, plugins will be allowed to include their pagecataloging folder at the root level of the plugin zip folder. Upon enabling the plugin the JSONs will be read, validated, and Navigation/PageCatalog records will be added to the DB.

Note: Plugins with page catalog content are only supported on PowerSchool 23.5.0.0 or later. Attempts to install and enable them on earlier versions will fail.


Development Process
Make changes in the JSONs as needed, but make sure with each new change the version number is incremented.
Recommended Development Process Using 22.11.0.0 or Newer SIS
After making changes to JSONs, make sure to also increment the version in the plugin xml and re-zip the plugin.
Go to Plugin Management Console and update or delete/re-install the plugin.
Upon clicking enable:
The JSONs will be validate. If there are any validation errors they will be displayed in a drawer in the browser.
-- Correct the validation errors, then go back to step 1.
If there are no errors, Click the Enable button in the drawer.
After enabling the plugin, the JSONs will be read and after a page refresh the Navigation will be updated with the plugin’s links.
How to View ParentHTMLID and SortOrder of Existing Categories/Links
The values for parentHTMLID and sortOrder of existing categories/links are exposed in the DOM. The developer tools in your browser can be used to find these values. In order to view the values, right click on an item (category/link) in the left navigation and click on Inspect. This will open up the browser developer tools. The HTML element will have an attribute called data-custom-info that has these attribute values.

JSON Structure
The main property of the JSON is pages which hold an array of objects. Valid objects include a Category that contains child objects or additional subcategories and a child object that contains a reference to its parent category via the parentHTMLID property.

Caution: Do not use the following JSON as an example. It is strictly to show the structure of the JSONs to customize the Enhanced Navigation.
{
  "pages": [
      {
          "htmlID": "navFunctionsSection",
          "title": "psx.txt.wildcards.admin_nav_menu_left_css.functions",
          "iconName": "tools",
          "sortOrder": 400,
          "pageURL": null,
          "pageDescription": null,
          "districtLevelContext": 0,
          "contextType": "main",
          "version": "23.5.0.0",
          "children": [
              {
                  "htmlID": "navAttStatus",
                  "title": "psx.html.admin.functions.backfill_management",
                  "sortOrder": 100,
                  "pageURL": "/admin/attendance/functions/attendancestatus.html",
                  "districtLevelContext": 0,
                  "contextType": "main",
                  "version": "23.5.0.0"
              },
              {
                  "htmlID": "navAttStatus",
                  "title": "psx.html.admin.functions.backfill_management",
                  "sortOrder": 200,
                  "pageURL": "/admin/attendance/functions/attendancestatus.html",
                  "districtLevelContext": 0,
                  "contextType": "main",
                  "version": "23.5.0.0"
              }
          ]
        }
    ]
}
    
JSON Properties
JSON Key	Type	Description	Required
pages	Array	Root element, expected to exist by the parser. Holds all Navigation/PageCatalog JSON elements.	Yes
htmlID	String	The ID included on the element in the HTML. Must be Unique across all records in the DB. There is no support for updating htmlID for a record as of the writing of this document.	Yes
title	String	The name of the page, will be the text displayed in the link in the UI. Can be a message key or plain text.	Yes
iconName	String	Name of the PDS icon to be displayed for the Category. (App Nav view only)	No
sortOrder	Integer	Used to order the links in the navigation. Sort Order of Core links starts at 100 and increments by 100 as the list progresses. This is to provide room for multiple links to be placed between, before, or after any Core links.	Yes
pageURL	String	The URL to the Page. This property does not need to be included if defining a Category. PS-HTML tags are supported in this property. The URL must begin with "/admin".	No
originalParentUrl	String	The URL of the link list or landing page which may have originally contained the link the navigation record represents. The use cases are as follows:
Single OriginalParentUrl: User needs access to this OriginalParentUrl page in order to have the page in the table visible in the left nav in the updated navigation.
“OriginalParentUrl1>OriginalParentUrl2” : ‘>’ denotes that url1 is grandparent and url2 is parent (in the old UI) to the page in the table. The user needs access to both url1 and url2 in order to see the page in the left nav in the updated navigation.
“OriginalParentUrl1,OriginalParentUrl2" : ’“,” denotes that the page in the table is on both of these pages (in the old UI). The user needs access to either url1 or url2 in order to see the page in the left nav in the updated navigation.
No
districtLevelContext	Integer	Determines if a link is to be shown in the District Office or School Context. 0 = both School and District, 1=School only, 2=District Office only. Default if left out is 0.	No
contextType	String	Determines the Navigation Context the Link belongs to. Currently the only supported navigation contexts are main, student, and staff. If not provided the record is considered to be just a PageCatalog record.	No
requiredContext	String	Specifies whether a selection is required to visit the page. If a context is specified the user will be forced to make a selection before continuing to the provided link. This will also be used in Global Search, not required. Currently, the only supported required contexts are student and staff.	No
version	String	Version of the link. Used to determine if a link has been updated. Any incrementation to the version number indicates the file has changed and the SIS should update the DB with the record. Format should follow normal versioning strings with numbers at each level {major}.{minor}.{patched/hotfix}.{development_version} example: 23.5.0.1.	Yes
children	Array	Array of Navigation/PageCatalog JSON elements which fall under the parent Category.	No
parentHTMLID	String	Should be the htmlID of an existing Category that the link should be added to. Not used if the link is defined in a category’s children array. See examples.	No
isNewTab	Boolean	Setting this to true indicates that the page will be opened in a new browser tab.	No
isLandingPage	Boolean	Setting this to true indicates that the page contains a collection of links to child pages. An example would be a list of custom report pages. Those child pages can optionally be added as children of the page so that they appear in the navigation menu.	No
checkParams	Boolean	This value tells the framework that all query parameters in the URL are to be considered during the active link check. This is used when there multiple links with the same URL path but they have different query parameters which indicate which version of the page to show.	No
